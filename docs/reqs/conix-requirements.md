# Conix 需求规格

## 1. 定位

Conix 是跑在终端里的 agent 工作台，引擎是 Agix。它是 Agix 的参考宿主，用来展示 Agix 独有的能力：

- 一个进程跑多个会话
- 无人值守
- 子 Agent 与任务看得见、管得着
- 按流程执行长线任务
- 定时作业

Conix 不和 Claude Code、Codex、opencode 拼"聊天写代码"的打磨程度。对话区只是入口，右栏才是区别所在。

**目标用户**：在本机或服务器上让 agent 长时间干活，并且需要随时查看、随时介入的人。场景不限于编程，运维、调研、写作、数据处理都包括在内。

**项目级**：Conix 在一个项目里运行，一个实例绑定一个项目目录，agent 缺省只在这个目录里干活。会话、流程、作业都属于这个项目，**只在项目里**：没有全局的流程与作业。内置的流程和插件带来的流程是只读的，每个项目都能用，项目里同名的取代它。要"全局"的，就用**个人项目**：缺省是文档目录下的 `Conix`（macOS、Linux、Windows 各按自己的"文档"目录，如 `~/Documents/Conix`），它和别的项目一样，不做特别区分；只是它由 Conix 建在用户自己的文档目录里，第一次用就信任，不用先 `/trust`。家目录本身不能当项目（它的 `.conix` 就是全局目录），在家目录、根目录或全局目录里运行 `conix` 进的是个人项目。在项目目录里运行 `conix` 就接入这个项目的实例（没有就新建）；接别的项目用 `conix list` / `conix attach`（阶段 3 实现，mock 的实例路径是虚构的，阶段 2 仍从选择框进）。

**远程怎么用**：ssh 登录到那台主机，在上面运行 `conix`，接入已经在跑的实例。Conix 不监听任何网络端口，远程访问的安全完全交给 ssh 和操作系统。

## 2. 术语

| 词 | 含义 | 来自 |
|---|---|---|
| 实例 | 本机上一个常驻的 Conix 宿主进程。引擎、它的会话、流程运行、作业都在实例里。TUI 关掉以后实例继续跑，下次可以重新接入。一台机器上可以有多个实例 | Conix |
| 接入 / 脱离 | TUI 连上某个实例叫接入；TUI 退出、实例继续运行叫脱离。**一个实例同一时刻只能有一个 TUI 接入** | Conix |
| 会话 / 主 Agent | 用户直接对话的那个 agent。一个会话对应一个主 Agent | Agix 会话 |
| 子 Agent | 主 Agent 派出去的 agent，有自己的侧链会话，还可以继续往下派 | Agix `Agent` 工具，任务 `kind: agent` |
| 任务 | 在会话之外继续跑的工作：子 Agent、团队成员、Shell 命令、监视器、程序（RunCode）、MCP 任务、会话内的定时任务 | Agix `session.tasks` |
| goal | 会话目标：一轮做不完，引擎会自动开下一轮，直到完成、受阻或轮数用完 | Agix `session.goal` |
| todo | 主 Agent 自己维护的待办清单 | Agix `TodoWrite` 工具 |
| 流程 | 一份定义：由**站**组成的有向无环图，每一站有要做的工作和出口条件。格式与 Harnix 兼容 | Harnix flow |
| 运行 | 一个流程在一个主题上的一次执行，也就是流程的实例 | Harnix flow |
| 站 | 流程里判断的单位：做什么（skill + 执行者），怎样才算通过（输出契约、门禁、人工确认） | Harnix flow |
| 作业 | 定时触发的工作。**简单作业**是提示词加 skills，跑一轮对话；**流程作业**是启动一次流程运行 | Conix |
| 场景 | Agix 的 scene，决定有哪些工具、什么提示词、是否有人值守。Conix 不绑定在某一个场景上 | Agix scene |
| 会话归属 | 一个会话属于哪个实例、哪台主机、哪个项目、哪个场景，是怎么来的（用户新建、作业触发、流程派生、子 Agent、分叉） | Conix |

## 3. 使用场景

| 编号 | 场景 |
|---|---|
| S1 | 在本机项目目录里运行 `conix`，新建一个实例，和 agent 对话完成一件事。过程中能看到它派子 Agent、跑命令，可以中途批准或插话 |
| S2 | ssh 到服务器，运行 `conix`。屏幕上列出这台机器上正在跑的实例，选一个接入，接着处理它的事情：几个子 Agent 在右栏一目了然，挑一个点进去看它在做什么 |
| S3 | 下班前从实例脱离，关掉终端，ssh 也断开。实例里的流程和作业照常运行。第二天 ssh 上去再接入，一切都在 |
| S4 | 在对话里设计一个流程（比如"需求 → 设计 → 实现 → 评审"），先试运行，确认后保存。之后对不同主题启动多次运行，每一站都可以检视、确认或返工 |
| S5 | 定义作业：每天 9 点跑一次巡检（简单作业）；每周一对上周的工单跑一遍"分类 → 汇总 → 待确认"流程（流程作业）。打开 Conix 就能看到历史，并能点进每一次运行看结果 |
| S6 | 好几个会话、运行、作业都在等人处理（审批、确认、受阻、失败），按一个键就依次跳过去处理 |
| S7 | 在机房的物理控制台上用 Conix：终端尺寸固定、不能调整，只能单栏显示，用快捷键在对话区和右栏之间切换，并且始终看得到怎么切回来 |

## 4. 功能需求

优先级：

- **P0**：阶段 2（mock）必须做完并验收。
- **P1**：阶段 2 先做出界面，接缝之后再完善。
- **P2**：以后再说。

### 4.1 实例与连接（I）

| 编号 | 需求 | 优先级 |
|---|---|---|
| I-01 | 运行 `conix` 时，如果本机已有在跑的实例，而命令行里又没要求新建，就先弹出 TUI 选择列表：接入某个已有实例，或者新建一个。没有在跑的实例时直接新建并接入 | P0 |
| I-02 | `conix new [--name 名字] [--project 目录]`：新建实例并接入，不经过选择列表 | P0 |
| I-03 | `conix list`：用纯文本列出本机的实例，包括名字、PID、项目、运行时长、会话数、在等人的数量，以及当前是否已被接入（被谁接入：用户、终端、ssh 来源，空闲了多久）。加 `--all` 时，已停止但还保留状态的实例也一并列出 | P0 |
| I-04 | `conix attach <名字>`：接入指定实例；`conix start <名字>`：启动一个已停止的实例，恢复它的运行和作业；`conix stop <名字>`：停止实例 | P0 |
| I-05 | TUI 里退出（Ctrl+D、`/quit`）就是**脱离**，实例继续运行。`/stop` 才是停止实例，并且要二次确认 | P0 |
| I-06 | **只允许一个 TUI 接入。** 实例已被接入时，再去接入会被拒绝，并显示占用者的信息；可以选择**强制接入**：踢掉当前那个 TUI，自己接入。被踢的一方会看到是谁、在什么时候把它踢掉的 | P0 |
| I-10 | **空闲脱离。** 已接入的 TUI 如果超过设定时间没有任何输入，就自动脱离，把实例让出来。超时时长可以在配置里设，也可以在 `conix attach --idle-timeout <时长>` 时指定，设为 `0` 表示不超时 | P0 |
| I-11 | **连接保活。** TUI 与实例之间定时发心跳。TUI 进程僵死、或 ssh 断开但连接还挂着时，实例在几次心跳都没收到之后主动断开这个连接，避免实例一直被一个已经不在的客户端占着 | P1 |
| I-07 | 只通过本机的 unix socket 连接。socket 文件权限 0600、所在目录 0700，并校验连接对端的 uid。**不监听任何网络端口。** 远程使用就是 ssh 登录后在那台机器上运行 `conix` | P0（界面）/ P1（真实） |
| I-08 | 实例意外退出后，下次 `conix list` 要能识别出来，并清掉残留的 socket 和发现文件 | P1 |
| I-09 | 实例与 TUI 的连接意外断开时，界面显示连接状态，并自动重连。重连后补齐断开期间的内容。如果重连时发现实例已经被别人接入，就不再重试，并显示占用者的信息 | P0（界面）/ P1（真实） |

### 4.2 布局与终端（L）

| 编号 | 需求 | 优先级 |
|---|---|---|
| L-01 | 左边是对话区，右边是标签栏：会话 / 流程 / 作业 | P0 |
| L-02 | 宽屏（≥ 120 列）时左右并排，比例可以调；窄屏时只显示一栏，用快捷键在两栏之间切换 | P0 |
| L-03 | 右栏可以整体收起，只保留对话区 | P0 |
| L-04 | 标签头上显示"等你处理"的数量（审批、确认、受阻、失败） | P0 |
| L-05 | 一个键跳到下一处等你处理的地方，可以跨会话、运行和作业（S6） | P0 |
| L-06 | **启动时主动设置终端尺寸**：按配置里的缺省大小（如 160×45）请求终端调整窗口。终端不响应时就按实际尺寸来。退出时把窗口恢复到原来的大小。在 tmux 或 screen 里、或者配置关掉时不发这个请求 | P0 |
| L-07 | **底栏始终显示最基本的几个键：切块、换标签、切栏、退出、帮助**：无论焦点在哪、打开着哪个浮层、处于什么模式，底栏最右边都有它们，避免在尺寸不能调的终端上切过去就回不来（S7） | P0 |
| L-08 | **退出要问一句**：Ctrl+X（以及连按两次 Ctrl+C / Ctrl+D、`/quit`）弹出选择：后台运行（脱离，实例继续）/ 直接退出（停止实例）/ 返回 | P0 |
| L-11 | **多语言**：界面文字（含底栏、帮助、提示、配置文件模板、命令行帮助）全部来自语言资源，内置中文、英文；`ui.language`（zh / en / auto）或 `CONIX_LANG` 选择。加一种语言只需加一套资源文件：内置的放 `crates/i18n/locales/<语言>/`，用户自己的放 `~/.conix/locales/<语言>/`，不改代码。缺的文字退回中文。会话内容、流程与作业的名字等数据不翻译 | P0 |
| L-09 | **配色可配置**：`~/.conix/conix.yaml` 的 `ui.theme`，预设 claude（橙）与 aqua（水蓝），可逐项覆盖；框线是弱灰、有焦点时是亮灰，焦点标题条用主色；代码块语法高亮的主题也可选。配置文件不存在时生成一份带注释的缺省配置 | P0 |
| L-12 | **命令键只用 Ctrl+字母**（帮助另留 F1）：不靠 F 键和 Alt，它们在笔记本键盘、macOS 终端上不一定按得出来或收得到；底栏与帮助里写成 `^G` | P0 |

### 4.4 对话区（C）

对话区显示的是一个**上下文**，可能是以下几种之一：某个主 Agent 的会话、某个子 Agent 的侧链会话、某次流程运行的主会话，或者还没开始的新会话草稿。流程与作业没有自己的会话：建、改、清理都在用户会话里说。

| 编号 | 需求 | 优先级 |
|---|---|---|
| C-01 | 流式显示回答正文与思考过程，思考过程可以折叠 | P0 |
| C-02 | 工具调用画成块，结果超过阈值时自动折叠，可以选中后展开或收起；修改文件的结果显示 diff | P0 |
| C-03 | 模型某一步失败、被重新发起时，丢掉这一步已经画出来的文字 | P0 |
| C-04 | 权限审批：允许一次、本会话总是允许、拒绝（可以写理由）。多个审批排成队列，可以在它们之间切换 | P0 |
| C-05 | 模型提问：选项题可以用上下键、数字键或鼠标选，也可以自由输入；引擎撤回提问（超时、被取消）时，对话框随之消失 | P0 |
| C-06 | 中断正在跑的这一轮 | P0 |
| C-07 | 运行中继续输入：缺省是插话（steer），在下一个步骤边界进入对话；没赶上而被退回的消息要放回输入框 | P0 |
| C-08 | 输入框：多行、历史、按词或按行编辑、粘贴 | P0 |
| C-09 | slash 命令补全：本地命令，加上引擎为这个会话提供的命令表 | P0 |
| C-10 | 状态行：显示这一轮在做什么、耗时和 token；压缩上下文时显示"压缩中" | P0 |
| C-11 | 转录可以滚动；有新内容时给出提示，一键回到底部继续跟随 | P0 |
| C-12 | **归属**：实例、主机、项目目录、场景、模型在顶栏（`[CONIX] 实例@主机  项目  场景  模型`）；会话的来源（作业「…」触发 / 流程「…」的某一站 / 子 Agent 的上级 / 从哪个会话分叉）与状态在对话框标题右边 | P0 |
| C-13 | 切换模型（`/model`），从下一轮起生效，以引擎的确认为准 | P1 |
| C-14 | 侧问 `/btw`：不打断当前这一轮、不污染主对话，在分叉出来的会话上问一句 | P1 |
| C-15 | 通知：模型主动发的提醒、引擎的提醒，显示在底栏，过一段时间自动消失 | P1 |
| C-16 | 在子 Agent 的上下文里，输入的内容通过"给任务发消息"送达这个子 Agent；只读的上下文（任务已经结束）禁用输入框 | P0 |
| C-17 | **对话区照 Claude Code**：凡 Claude Code 也有的部分（转录的块样式、状态行、输入框、提问框、快捷键），外观与按键都与它一致；Conix 独有的部分在此基础上加（交互 §4、§7） | P0 |
| C-18 | 开场欢迎块：Conix logo、版本、实例、项目、场景、模型、常用键 | P0 |
| C-19 | ^O 看转录（展开成详细，再按回输入框）；^T 收放对话区顶部面板；空输入框按 `?` 打开快捷键 | P0 |
| C-20 | Shift+Tab 轮换权限模式，输入框下方显示当前模式。模式是会话的：切了立即生效、跨重启保留（Agix `session.setPermissionMode`）；比设置宽的被夹回时说明实际模式 | P0 |
| C-21 | `@` 文件提及补全；`!` 命令模式；搜历史（键另定，^R 已给待处理）；空闲时连按两次 Esc 回到上一条消息重新编辑 | P1 |

### 4.5 会话标签（S）

右栏分上下两段。**右栏只放摘要与导航，详细的看、改都在左边的对话区**；右栏里选中任何带会话的
东西（主 Agent、子 Agent、运行的主 Agent、站里的子 Agent），左边对话区就跟着切过去（S-10）。

| 编号 | 需求 | 优先级 |
|---|---|---|
| S-01 | **上半是主 Agent（会话）列表**：每行显示名字、状态、归属（项目、场景、来源图标）、token；可以按项目或来源过滤 | P0 |
| S-02 | 展开一个主 Agent，显示它的 **goal**（目标、阶段、轮次、受阻原因）和 **todo**（完成数 / 总数，以及每一项） | P0 |
| S-03 | goal 的操作：设定、暂停、恢复、修改、清除 | P1 |
| S-04 | **下半是选中主 Agent 的拆分树**：主 Agent → 子 Agent（可以递归）→ 任务。每个节点显示类型、状态、耗时、token；在等人的节点要高亮 | P0 |
| S-05 | 在树上选中子 Agent，按 Enter，对话区切到它的侧链会话；选中 Shell 或监视器任务，查看它的输出并实时跟随 | P0 |
| S-06 | 任务的操作：停止、发消息 | P0 |
| S-07 | 新建会话：选择项目、场景、模型 | P0 |
| S-08 | 打开历史会话（恢复）、重命名、关闭。会话已经在另一个实例里打开时，明确提示是哪个实例占着 | P0 |
| S-09 | 已经结束的子 Agent 和任务缺省收起，可以展开 | P1 |
| S-10 | **选中即切换**：右栏选中带会话的行，左边对话区跟着切，不用按 Enter；面包屑带上它的上一层；选中没有会话的任务看它的输出 | P0 |
| S-11 | 对话区顶部面板：普通会话显示 goal 与 todo（约占 1/3，有就打开，没有就没有面板）；标题 Goal & Todo 靠右，^T 在下沿右边，收起时只剩一条线；流程、运行、作业的会话同一个机制 | P0 |
| S-12 | 拆分树里子 Agent 与任务用图标区分：`◆` 子 Agent，`$` shell、`◉` monitor、`λ` 程序、`⚙` MCP | P0 |
| S-13 | 会话列表只列人发起的会话（新建、分叉），它们是一级公民：流程与作业都在这里说话来操作。流程运行、作业触发开出来的会话从流程、作业标签进。第一行是"新建会话"（也可以 `/new`）；启动即是新会话草稿，不输入就不建会话 | P0 |
| S-15 | 右上三个列表每行带 `#n`：此刻在列表里的位置，随列表变；每项另有不变的 ID。对话里说 `#3` 或 ID 都能指到它 | P0 |
| S-16 | 每个会话都有会话、流程、作业的工具，查看不问人，改东西走权限询问。**外面只管生命周期**：用户会话能启动、暂停、恢复、取消、重跑流程运行，确认、放行、强制放行、返工、重试它的站；能新建、修改、删除、启停、立即运行作业，停下正在跑的那次。**不能动运行与触发里面的会话**（改名、关闭、删除、发消息、代答、授权），那些只在 TUI 里切到那个会话自己处理。运行里、触发里的会话对流程与作业只能看，不能操作自己所在的运行或作业 | P0 |

### 4.6 流程标签（F）

同样是上下两段：上半是流程定义（展开后是它的各次运行），下半是选中那次运行的各站。

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-01 | 列出流程定义：名字、标题、来源（项目 / 内置 / 插件）、正在运行的数量 | P0 |
| F-02 | 展开一个流程，列出它的运行：主题、状态（运行中 / 等待 / 暂停中 / 已暂停 / 已完成 / 已取消）、当前站、耗时、token | P0 |
| F-03 | 选中一次运行，下半是它的整棵树：主会话 → 各站 → 站的任务 → 子 Agent 与任务（Shell、监视器、程序……），一层层往下。每个节点带状态、耗时、token 与**模型**（不同的站、子 Agent 可以用不同的模型）。站的状态有：待进入、搁置、进行中、未达标、已通过、已跳过、待重做。并行的站用缩进表示，不画图 | P0 |
| F-04 | 选中树上任一个有会话的节点（主会话、站的会话、子 Agent），对话区切到那个会话：可以插话、回答它的提问、批它的权限，在这里处理运行里面的事 | P0 |
| F-05 | 运行的操作——确认、放行（搁置的站）、强制放行（要写理由）、返工（选择退回到哪一站）、重试失败的任务、暂停、恢复、取消、重跑（同流程、同主题、同输入再跑一次）——**都在用户会话里说**，由实例的流程工具执行；改东西的工具照常问人，不可逆的那一问就是二次确认。界面上不放这些操作的键：`m` 把选中的运行或站作为话头放进输入框 | P0 |
| F-06 | 启动一次运行：在用户会话里说，由实例的流程工具执行 | P0 |
| F-07 | 选中一个流程定义时，对话区不动，右下是**流程设计**（分层节点图、每站的执行方式 / skill / 出口条件、汇合）；在用户会话里设计或修改流程、校验、试运行、保存（`n` 新建、`m` 说这一个），右下随定义刷新。流程还有没结束的运行时不许修改、删除，右下标出锁定 | P0 |
| F-08 | 查看原始 YAML（`v`）；在右下选中一站，`v` / Enter 看这一站的配置 | P0 |
| F-09 | 项目的流程与内置、插件带来的流程区分：后两者只读、每个项目都有，名字前标 `◎`；项目里存一份同名的就取代它，删掉回到原来那份 | P0 |
| F-09 | 流程格式与 Harnix 兼容：同一份流程包在两边都能跑 | P1 |

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| N-01 | 80 × 24 的终端可以用（单栏），120 列以上并排 |
| N-02 | 流式输出的开销与转录的长度无关：来一个 token，只重算它所在的那个块 |
| N-03 | 任何 IO（列会话、读历史、读任务输出、连接实例）都不阻塞界面，按键随时有响应 |
| N-04 | CJK、emoji、制表符按显示宽度正确排版 |
| N-05 | 阶段 2 的所有交互都不需要网络、API key 或 Agix；mock 场景完全确定，可以重放 |
| N-06 | 常见终端都能用：iTerm2、Terminal.app、kitty / WezTerm、Linux 物理控制台、tmux 里、通过 ssh |
| N-07 | 终端不支持的按键（如 Shift+Enter）必须有替代键；鼠标能做的事，键盘都能做，键盘能做的事，不要求鼠标都能做 |

## 6. 不做

- 监听网络端口（TCP / WebSocket）。远程访问一律通过 ssh 登录。
- ACP。已经作为需求提给 Agix（harnixai/Agix#74），Conix 本身不做。
- Web 界面。
- Vim 模式。
- 在终端里显示图片。
- 在 Conix 里改 Agix 或 Harnix 的代码。缺什么就到对应的仓库提 issue。

## 7. 依赖与缺口

| 需要 | 现状 | 处理 |
|---|---|---|
| 数据目录用 `~/.conix` | Agix 的全局数据根可以通过 `EmbedConfig::new(data_root)` 指定 | 直接支持 |
| 项目里的配置目录也叫 `.conix` | Agix 把项目层的 `<项目>/.agix/`（项目设置、规则、agents、hooks、worktrees 等）写死在 40 多个文件里，其中包括路径安全和沙箱掩码 | 已提 harnixai/Agix#86（`EmbedConfig.project_dir`，安全保护随名字生效）。落地之前先沿用 `.agix/`，落地之后改成 `.conix/` |
| todo 列表 | Agix 没有专门的方法或事件，只能从 `TodoWrite` 工具调用的入参里读出来 | 接缝时先从事件里取，不够用再给 Agix 提 issue |
| 流程 | 不在 Agix 里，在 Harnix 的 flow 里 | 拷贝到 `3rds/harnix-flow`，等 Harnix#66 拆分完成 |
| 作业 | Agix 的 `schedule.*` 只能定时跑一轮对话，启动不了流程 | 由 Conix 实例自己调度 |
| 侧问 | Agix 提供 `session.fork` | C-14 接缝时使用 |
| 多个实例共用 `~/.conix` | Agix 的 `EmbedConfig.instance` 锁的粒度是"数据根 + 场景"，同一个场景只能有一个 | Conix 不传 `instance`，由自己管实例锁；进程组的登记用每个实例自己的 `groups_file`。同一个会话被两个实例同时打开时，Agix 的会话写者锁会拒绝后来的那个，界面上提示是被谁占着（S-08） |
