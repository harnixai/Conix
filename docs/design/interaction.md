# Conix 交互规格

这份文档是阶段 2 用 mock 验收的依据。这里写的每一条，都必须能在 mock 下实际操作出来，并且有对应的场景覆盖（场景编号见 `testing.md` §4）。需求编号见 `docs/reqs/conix-requirements.md`。

## 1. 区域与命名

每个区域只有一个名字，下表三列写法都指同一个区域。代码路径用于代码、提交说明和 bug 报告，它就是 `FrameState` 里的字段路径。

| 代码路径 | English | 中文 |
|---|---|---|
| `instances` | Instance Picker | 实例选择（整屏） |
| `header` | Header | 顶栏 |
| `chat` | Chat Pane | 对话区 |
| `chat.crumbs` | Breadcrumbs | 对话·面包屑 |
| `chat.panel` | Context Panel | 对话·顶部面板（goal / todo、运行进度，§4.3） |
| `chat.transcript` | Transcript | 对话·转录 |
| `chat.status` | Status Line | 对话·状态行 |
| `chat.composer` | Composer | 对话·输入框 |
| `chat.picker` | Picker | 对话·补全列表（浮在输入框上方） |
| `chat.ask` | Ask Box | 对话·提问框（审批与模型提问，盖在输入框的位置上） |
| `divider` | Divider | 分隔线（左右栏之间，可以拖动） |
| `side` | Side Pane | 右栏 |
| `side.tabs` | Tabs | 右栏·标签头 |
| `side.upper` | Upper List | 右栏·上半 |
| `side.lower` | Lower Tree | 右栏·下半 |
| `footer` | Footer | 底栏（快捷键提示、通知、二次确认） |
| `overlay` | Overlay | 浮层：帮助、表单、查看器，同一时间只有一个，写作 `overlay:help` 这种形式 |

## 2. 启动与布局

### 2.1 启动

```
conix ──► 本机有在跑的实例？──否──► 新建实例 ──► 工作台
              │是
              ▼
          实例选择（2.2）──► 接入 / 新建 ──► 工作台
```

**终端尺寸协商（L-06）**：在进入备用屏之前完成。

1. 先请求缺省尺寸（`config.toml` 中的 `ui.initial_size`，缺省值 160×45）。
2. 终端在 300ms 内调整了，就按新尺寸布局；没调整，就按实际尺寸布局。整个过程用户感觉不到。
3. 退出时如果改过尺寸，就请求恢复到原来的尺寸。
4. 以下情况不发起请求：在 tmux 或 screen 里，或者配置成 `off`。

### 2.2 实例选择（I-01）

```
┌ Conix · 选择实例  主机 ops-01 ────────────────────────────────────────┐
│                                                                       │
│  › ● dev        ~/work/auth     运行 3h12m   会话 4   ◐ 等你 2          │
│    ● ops        /srv/ops        运行 6d      会话 9   🔒 me@pts/3 (ssh 10.0.0.7) 空闲 41m │
│    ○ research   ~/notes         已停止（11-14）                          │
│    ✗ old        ~/tmp           残留 · 已清理                            │
│                                                                       │
│    ＋ 新建实例                                                          │
│                                                                       │
└ Enter 接入/启动 · n 新建 · s 停止 · q 退出 · ^H 帮助 ───────────────────┘
```

- 每一行都可以用鼠标操作：单击选中，双击接入；已停止的实例双击就是启动。
- **已被接入的实例**（🔒）：会显示接入者（用户、终端、ssh 来源）和已空闲的时长。按 Enter 会提示"已被占用，强制接入会踢掉对方？ y / n"；按 `f` 直接进入强制接入的二次确认。
- 选中"新建实例"并按 Enter，弹出表单：名字（缺省自动生成）、项目（缺省为当前目录）。
- 停止实例需要二次确认。

### 2.3 宽屏（≥ 120 列）：两栏并排

三块各自框起来：对话区、右上（标签与列表）、右下（选中项的拆分）。每块的标题写在框的上沿，不带底色（顶栏、底栏带底色；浮层与实例选择框的标题同样不带底色）：和右上的标签头一个做法，有焦点的那一块框线变亮、左标题换主色加粗，没焦点时是淡色；右边的摘要（会话状态、"5 个在跑"）始终是淡色。字段式的内容（站的配置、作业的定义）名字右对齐、后面跟 `: `，值从同一列起左对齐，列宽按最长的名字。

```
 Conix · 实例 dev@ops-01 · ~/work/auth                                         ● 已连接   ← 顶栏（底色）
╭ 会话 › 重构认证模块 ─────────────────── ● 运行中 ╮╭ 会话 ② │ 流程 │ 作业 ① ──────────────╮
│ dev@ops-01 · ~/work/auth · code · sonnet-5-5     ││▾ ● 重构认证模块              41k    │
│                                                  ││    goal ◐ 迁到 OAuth · 第 2 轮       │
│ > 帮我把认证迁到 OAuth                            ││    todo 3/7                         │
│                                                  ││▸ ◐ 日志巡检 ⏰               12k    │
│ ⏺ 我先看一下现有的认证入口……                     ││                                     │
│                                                  │╰─────────────────────────────────────╯
│ ⏺ Read(src/auth/mod.rs)                          │╭ 重构认证模块 ─────────── 2 个在跑 ──╮
│   ⎿  Read 42 lines                               ││● 主 Agent                 运行中 2m │
│ ⏺ Bash(cargo test auth)                          ││▾ ◐ reviewer  子 Agent   等你批准     │
│   ⎿  running 18 tests …                          │││   └ ● cargo test  shell      1m    │
│                                                  ││└ ● tail app.log  monitor            │
│ ✻ 思考中… (12s · ↑ 3.2k tokens · esc 中断)        ││                                     │
│ ╭──────────────────────────────────────────────╮ ││                                     │
│ │ > █                                          │ ││                                     │
│ ╰──────────────────────────────────────────────╯ ││                                     │
│   ? 快捷键                        ⏵⏵ 自动接受编辑 ││                                     │
╰──────────────────────────────────────────────────╯╰─────────────────────────────────────╯
 ^R 待处理(3) · ^O 看转录 · ^T 面板        ^G 切块 · ^N 标签 · ^B 切栏 · ^X 退出 · ^H 帮助   ← 底栏（底色）
```

- 左右比例缺省 60 : 40。调整方式：拖动两栏相接的那道边框；焦点在右栏时也可以按 `<` / `>`，每次 5%。范围 40%–75%，调过后记住。
- **右栏上下两块平分高度**。
- 对话区框的标题是面包屑，右侧是这个会话的状态；右上框的标题就是标签头；右下框的标题是右上选中项的名字，右侧是它的摘要（如"2 个在跑"）。
- 焦点在右栏下半时，标签头上当前的标签仍是选中色：下半是它的延伸。只有当前标签用主色；
  有待处理的标签文字不变色，后面跟一个提醒色的 `◐`（提醒色与主色太近，整个标签变色会被看成选中）。
- **选中行**用暗调的橙底（主题项 `selected_bg`），行首 `›`。没焦点的那一块也留着选中，底色暗一档
  （`selected_bg_inactive`），`›` 变淡：焦点在右下时右上的选中仍看得见，焦点在左边时右栏的选中就是
  左边在看的那个（§5）。底色要暗：行里的提醒色、主色、绿红状态色落在上面都得看得清。
- ^B 收起右栏，对话区占满全宽。

### 2.4 窄屏（80–119 列）与尺寸固定的终端：单栏

- 同一时间只显示一栏，**^B 在对话区和右栏之间切换**。
- 显示对话区时，顶栏右侧标出右栏的待处理角标；显示右栏时，上下两段都占满整宽。
- **底栏最右边永远有 `^G 切块 · ^N 标签 · ^B 切栏 · ^X 退出 · ^H 帮助`**（L-07）：最基本的走动与离开。在任何焦点、任何浮层、任何二次确认里都显示，保证在物理控制台这类尺寸不能调的终端上，切过去之后一定切得回来。
- 底栏空间不够时，从左边开始砍提示，这几项永远保留。
- Ctrl+字母写成 `^G`（nano、终端手册的写法），省地方，也是终端用户都认得的。

### 2.5 极窄（< 80 列或 < 24 行）

仍然是单栏，底栏只保留那几项。宽度不到 60 列时，屏幕中间只显示"终端太小（需要至少 60 列）"，底栏照常显示。

## 3. 焦点

```
        ┌──────────── ^G ────────────┐
        ▼                            │
Composer ──^G──▶ Side.Upper ──^G──▶ Side.Lower
   │ ▲               ▲
 ^O│ │^O / Esc       └── ^N：换到下一个标签（会话 → 流程 → 作业），焦点进右上
   ▼ │
Transcript
Dialog（提问框、浮层、二次确认）：模态，关掉才能移走焦点
```

- **^G 在三大块之间转**：输入框 → 右上 → 右下 → 输入框。右上停在当前标签，不换标签；换标签是 ^N，
  换过去焦点就在右上，再按 ^G 就到它的右下。单栏时转到另一栏的块会自动换栏显示。回到左边时有提问在等，
  就直接进提问框。
- **顶部面板（左上）不拿焦点**：它只是摘要（Goal & Todo、运行进度），完整内容在右栏会话树、流程运行树里。
  ^T 收放它，焦点回到输入框；内容放不下时用滚轮滚，点标题线或下沿也是收放。
- **转录不进 ^G 这一圈**（不然一圈太长）：^O 进去看（同时展开成详细），^O 或 Esc 回输入框；点它也能进。
- 命令键只用 Ctrl+字母（F1 例外，帮助人人都知道）：F 键在笔记本上要按 Fn，Alt 在 macOS 要终端设成
  Meta 才收得到；Ctrl+方向键在 macOS 上默认被调度中心、切换桌面拿走，Ctrl+空格是切换输入法。
  Ctrl+I / M / [ 就是 Tab / 回车 / Esc，Ctrl+数字多数终端发不出来，也都不用。

- **滚动：哪一块有焦点滚哪一块，键都一样**——PageUp / PageDown 一页，Shift+↑ / Shift+↓ 一行；
  鼠标滚轮滚指针下面那块（包括顶部面板）。
  - 输入框：输入的字超出了框就滚输入区（编辑一下就回到光标处），没超出就滚转录——边打字边
    往回翻对话最常见，不必先离开输入框。
  - 转录：滚转录。右栏上半 / 下半：移动选中行，列表跟着滚。浮层：滚浮层。

- 启动后焦点在 Composer。
- Esc：**有一轮在跑、焦点在输入框时是中断**（与 Claude Code 一致）；其余时候是"退一步"：关浮层或二次确认 → 收起补全列表 → 从右栏回到 Composer → 对话区的上下文退一层。
- 有焦点的那一块，框线与标题条高亮；底栏提示随焦点变。
- **提问框弹出时不抢焦点。** 正在打字时，后面敲的键不会变成对提问的回答。按 ^R 或用鼠标点它才进入。没有在打字时（输入框为空），提问框直接得到焦点，与 Claude Code 一致。

## 4. 对话区

### 4.1 上下文与归属（C-12、C-16、F-04、F-07）

| 上下文 | 怎么进入 | 输入框 | 面包屑 |
|---|---|---|---|
| 草稿 | 启动时；会话标签的 `＋ 新建会话`、`n`、`/new` | 第一句话提交时才建出会话；没输入就不记录 | `会话 › 新会话（输入即开始）` |
| 主 Agent 会话（用户会话） | 会话标签上半选中（Enter 进输入框） | 正常对话；流程、作业也在这里说着改 | `会话 › <名字>` |
| 子 Agent | 会话标签下半选中 | 消息经"给任务发消息"送到它；任务已结束则只读 | `会话 › <主> › <子>` |
| 任务输出 | 下半选中 Shell、监视器等没有会话的任务 | 只读，实时跟随 | `会话 › <主> › <命令>` |
| 运行主会话 | 流程标签里选中一次运行 | 可以插话 | `流程 › <流程> › <主题>` |

用户会话是一级公民：流程定义和作业**没有自己的会话**，新建、修改、删除它们都在用户会话里说
（每个会话都有流程、作业工具）。

**全局信息在顶栏**：`[CONIX] <实例>@<主机>  <项目目录>  <场景>  <模型>`。实例与项目是全局的，
场景与模型取当前对话区的会话。对话区里不再单占一行。

**会话的来源与状态**在对话框标题的右边（淡色）：`<来源> · <状态>`。`<来源>` 有以下几种（人新建的不写）：

- `作业「每日巡检」`
- `流程「需求到上线」› 支付重试 › 实现`
- `子 Agent ← <上级会话>`
- `⑂ 分叉自 <会话>`

宽度不够时截断。会话在另一个实例里被打开（被占用）时，这里加上 `⚠ 被实例 <名字> 占用`，同时输入框变成只读。

每个上下文各自记住滚动位置、选中的块、折叠状态。

### 4.2 转录（照 Claude Code）

对话区里 Claude Code 也有的部分，一律照它的样子做；Conix 独有的（会话来源、子 Agent 上下文、流程会话）在此基础上加。

**开场**：打开一个会话（以及还没打开会话时），转录最上面是欢迎块：

```
╭──────────────────────────────────────────────────────╮
│  ▄▀▀ ▄▀▄ █▀▄ █ ▀▄▀                                    │
│  ▀▄▄ ▀▄▀ █▄▀ █ ▄▀▄   Conix 0.1.0                      │
│                                                      │
│  实例 dev@ops-01 · 项目 ~/work/auth                    │
│  场景 code · 模型 claude-sonnet-5-5                   │
│                                                      │
│  /help 帮助 · / 命令 · @ 提及文件 · ! 执行命令          │
│  ^G 切块 · ^N 换标签 · ^B 切栏 · ^R 待处理 · ^H 帮助  │
╰──────────────────────────────────────────────────────╯
```

**各种块**：

| 块 | 画法 |
|---|---|
| 用户输入 | `> 文本`，整块淡底色；多行时后续行缩进对齐 |
| 回答 | `⏺ ` 开头的正文，markdown 渲染（标题、列表、代码块、行内代码）；后续行缩进两格 |
| 思考 | 缺省折成一行 `✻ 思考了 3s (ctrl+o 展开)`；展开后是淡色正文 |
| 工具调用 | `⏺ 工具名(参数摘要)`：运行中 `⏺` 闪烁，成功绿色，失败红色；结果在下一行以 `  ⎿  ` 引出，缺省只显示前 3 行，多出的写 `… +42 行 (ctrl+o 展开)` |
| 文件修改 | `⎿  更新了 src/auth/mod.rs，+12 −3`，下面是带行号的 diff，`+` 绿底、`−` 红底 |
| todo 更新 | `⏺ 更新 todo` 后接清单：`☒` 完成、`◼` 进行中、`☐` 待做 |
| 通知 / 错误 | 淡色一行；错误红色 `⎿  Error: …` |

- **^O 看转录**：焦点进转录，同时整段展开成详细（所有工具结果与思考，与 Claude Code 的 ctrl+o 一样）；
  在转录里再按 ^O 或 Esc 回输入框，收回精简——详细是"看转录"的一部分，焦点怎么离开转录都收回。
  转录里 `o` 在精简与详细之间切；精简时 `[` `]` 选上一个 / 下一个块，Enter 展开或收起它。
- 一个块因 `StepRestarted` 作废时，直接消失（C-03）。
- 在最底部时自动跟随；往上翻之后停止跟随，底部出现 `↓ 有新内容 (End)`，可点。

### 4.3 状态行（照 Claude Code）

在输入框正上方，只有一行，互斥：

| 状态 | 显示 |
|---|---|
| 空闲 | 隐藏 |
| 运行中 | `✻ 思考中… (12s · ↓ 3.2k tokens)`：`✻` 动画，动词随阶段变（思考中 / 回答中 / 执行 Bash…），token 是这一轮已输出的约数、开始输出后才出现（与 Claude Code 一致）；同时输入框下那一行左边换成 `esc 中断` |
| 等人 | `◐ 等你批准：Bash(cargo test)` |
| 压缩中 | `✻ 压缩上下文…`：自动与手动的压缩都显示。压成了在转录里留一行 `上下文已压缩：12k → 3k tokens`；没压成也留一行说明（hook 拒绝、没有可压的、已取消为灰字，失败为警告色并带原因） |
| 已中断 | `⎿  已中断 · 你想让它怎么做？`，与 Claude Code 一致，留在转录里 |
| 断线 | `⚠ 与实例断开，重连中 (第 2 次)` |

**顶部面板**：对话框内第一行起是当前上下文的面板，不在转录里，不随对话滚走；高度按内容，最多占对话区的 1/3。

| 上下文 | 面板内容 |
|---|---|
| 普通会话（主 Agent、子 Agent） | goal 与 todo；两样都没有的会话没有面板 |
| 运行里的会话（主会话、独立会话的站、站里的子 Agent） | 运行进度：按进展上色的节点链、正在做或等人的站 |

流程设计、作业的执行情况不在这里：流程定义、作业没有自己的会话，它们在右下（§5.3、§5.4）。

```
───────────────────────────────────────────────────────── Goal & Todo ─
goal ● 迁到 OAuth，测试全绿 · 第 2/256 轮
todo 2/7
  ▶ 3. 实现 provider
  ☐ 4. 迁移 session 存储
  ✓ 1. 梳理现有认证入口
  ✓ 2. 调研 OAuth 库
────────────────────────────────────────────────────────── ^T 收起 ─
```

- 顶上一条线，**标题靠右**，只写它是什么（Goal & Todo / 流程设计：… / 运行：… / 作业：…）；状态别处都有，
  这里不重复。收放的快捷键在**下沿右边**（放不下要滚动时前面加 `↑2 ↓3 · 滚轮滚动 ·`）。
- 收起时只剩一条线：`────────── Goal & Todo  ^T 展开 ─`（快捷键是灰字，跟在标题右边），好知道这里有东西、随手打开。
  有面板的缺省打开；^T 按会话记住，按了焦点回到输入框。点标题线或下沿也是收放。
- 内容最多 10 行（也不超过对话区的 1/3），再多就在面板上用滚轮滚。面板不拿焦点（§3）：它是摘要，
  完整的在右栏。换了上下文回到顶上。
- todo 带编号；没做完的（`▶` 正在做、`☐` 待做）在上，做完的（`✓`）沉到下面，各组里仍按编号。
- Claude Code 的 Ctrl+T 是显示 todo 清单；这里同一个键收放面板，todo 也在面板里。

### 4.4 输入框（照 Claude Code）

```
╭──────────────────────────────────────────────╮
│ > 帮我看看 @src/auth/mod.rs 里的 token 校验█   │
╰──────────────────────────────────────────────╯
  ? 快捷键                        ⏵⏵ 自动接受编辑 (shift+tab 切换)
```

- 圆角框，提示符 `> `；空的时候显示淡色占位提示。多行时后续行缩进对齐，最多占对话区 1/3，超出在框内滚动。
- 框下一行：左边 `? 快捷键`（输入框为空时按 `?` 打开快捷键说明），运行中换成 `esc 中断`；右边是权限模式：`⏵⏵ 自动接受编辑`、`⏸ 计划模式`、`⏵⏵ 绕过权限`，缺省模式不显示（与 Claude Code 一致）。
- **Shift+Tab** 在权限模式之间轮换：缺省 → 自动接受编辑 → 计划模式（→ 绕过权限，仅在设置允许时）。
  **模式是会话的**：切的是对话区里的会话（在子 Agent 里时是它的根会话），立即生效（这一轮后面的工具
  调用就按新模式），记在会话上、实例重启后还在；换到别的会话显示它自己的模式。草稿上切的记在本地，
  第一句话建会话时带上。比设置宽的模式会被引擎夹回（缺省设置下只能收紧：自动接受编辑会落回缺省），
  底栏说实际是什么，再按一次接着往后轮。模型自己进出计划模式时，显示跟着变。
- 前缀：`/` 命令补全；`@` 文件提及补全（列出项目里的文件）；`!` 进入命令模式，框的提示符变成 `!`，提交的是一条 shell 命令。
- 换行：Shift+Enter；终端不支持时用 `\` 加 Enter 或 ^J。
- ↑ ↓ 翻历史。
- Esc 连按两次：输入框有字时清空并存进历史；为空时打开回滚，回到上一条消息重新编辑（P1，依赖 `session.rewind`）。与 Claude Code 一致。
- 运行中按 Enter 是**插话**：消息在转录里标为 `⧗ 待送达`，送达后去掉；被退回时放回输入框，底栏提示。
- 一次粘贴超过 10 行时，框里显示 `[粘贴了 42 行]` 占位，提交时展开。

#### 流程的地址

启动与操作用同一套地址。`<包>` 是流程包名；不在包里的流程，包名就是流程名（`/flow:brief`、`/brief:<站>`）。

| 写法 | 在哪能用 | 意思 |
|---|---|---|
| `/flow:<包>` | 全局 | 包的说明：流程、命令、在跑的运行 |
| `/flow:<包> <主题> [--k v] [--step]` | 全局 | 启动，按 flows.md §7.2 选路 |
| `/flow:<包>:<流程> <主题> [--k v] [--step]` | 全局 | 启动这条流程 |
| `/flow:<包>:<站> [运行] [理由]` | 全局 | 对这个包的某个运行做站操作 |
| `/flow:<包>:<命令> [--run <运行>] <参数>` | 全局 | 跑包的命令；不给运行就只有包的数据目录 |
| `/<包>` | 流程上下文 | 当前运行的状态：在哪站、欠什么、等谁 |
| `/<包>:<站> [理由]` | 流程上下文 | 站操作 |
| `/<包>:<流程> [理由]` | 流程上下文 | 换路（flows.md §7.3） |
| `/<包>:<命令> <参数>` | 流程上下文 | 跑包的命令，运行就是当前运行 |

- **名字的三种**：`:` 后面是流程、站还是命令，由包里的名字决定。包里这三类名字不重名（flows.md §7.1），所以不需要再加前缀；补全时每一项
  标上种类。
- **流程上下文**：当前对话是某个运行的会话（主会话或站的会话）。只有 `<包>` 正是这个运行的包时才由 Conix 接；别的 `/<x>:<y>`
  照旧交给 Agix（skill、插件命令）。
- **全局要写全 `/flow:`**：没有当前运行，`/xforge:apply` 指不到东西，而 `/<x>:<y>` 的形状本来是 Agix 的 skill 与插件命令；
  全局里认简写就会和它们撞。`/xforge:apply` 在全局照旧交给 Agix，找不到时提示用 `/flow:xforge:apply`。
- **本地路由，不经模型**：同 `/confirm`，发端口命令给实例，结果作为本地输出，不进会话。站操作是人对运行的操作，不该让模型来中转。
  模型那边的同一套名字是 `flow_start`、`flow_switch`、`flow_command`、`flow_rework`、`flow_retry`；人才能做的（确认、放行、强制）不给模型。
- **补全**：从流程目录与当前运行取。全局补 `/flow:` 之后的包、流程、站、命令；流程上下文补 `/<包>:` 之后的名字。
  还在等的模型建议（flows.md §7.5）在流程上下文的对话里与流程标签上列出来。

**站操作**：`/xforge:apply` 按运行此刻与这一站的关系做事：

| 这一站 | 做什么 |
|---|---|
| 是当前站，在 hold（`hold: true` 或步进） | 放行，开始派工 |
| 是当前站，在干活 | 显示它的任务与还欠的出口 |
| 是当前站，在等确认 | 显示，提示 `/confirm`、`/reject` |
| 是当前站，没达标或任务失败 | 重跑：有失败的任务重派，否则重跑出口判定（人改过东西之后用） |
| 在前面（过了的） | 打回到它，理由给重做的站（同 `/rework`）；有等着的模型建议指向它时，同时标成已接受 |
| 在后面 | 不跳：说当前站在等什么 |
| 被 `when` 跳过的 | 说它为什么被跳过 |

不跳站的原因：后面的站依赖前面的出口，跳过去等于绕过门禁。放行只认人，所以在 hold 的站上这条命令不会被模型代做。

## 5. 右栏

**原则：右栏只放摘要与导航，详细的看、改都在左边的对话区。**

- **选中即切换**：右栏里选中任何带会话的东西，左边对话区就跟着切过去，不用按 Enter。
  带会话的包括：主 Agent、子 Agent、流程运行的主 Agent、站里的子 Agent、作业触发出来的会话
  或运行；会话标签的 `＋ 新建会话` 对应草稿。Shell、监视器这类没有会话的任务，选中就看它的输出（只读）。
  **流程定义与作业没有会话：选中它们左边不动**，详情在右下。
- **选中按对象记**：列表插入、删除、重排、展开收起之后，选中仍是同一个对象；对象没了落在原来的位置。
  "选中即切换"也按对象判断：切标签、焦点回到右栏都不算换了选中，左边不动。
- **左边换了会话，右栏跟上**：草稿、面包屑退回、^R、从转录进子 Agent……左边换到的会话在当前
  标签的右上或右下看得见，就把选中挪到它（草稿对应 `＋ 新建会话`）。
- **各标签的落点**：^N 换到 / 点会话标签时，左边是草稿或某个用户会话（含它的子 Agent、任务输出）就留着，
  否则换到最近活跃（最近更新）的用户会话，一个都没有就是草稿；流程、作业标签左边不动。^N 是轮换的，
  从作业回流程要经过会话标签，也会这样落点；想留在运行的会话里就点流程标签头。
- **流程与作业的操作都在用户会话里说**（每个会话都有流程、作业工具）：新建、修改、删除，启动、暂停、
  恢复、取消、重跑运行，确认、放行、强制放行、返工、重试站，启停、立即运行、停下作业。流程、作业标签上
  按 `n`（新建）或 `m`（说选中的这一项），左边回到用户会话（已经在用户会话里就是它；在草稿上就留在草稿；
  否则是最近活跃的那个），把带序号与名字的话头放进输入框，如 `作业 #3「每日巡检」：`、
  `运行「支付重试」的站「评审汇总」（等确认）：`。改东西的工具照常问人，不可逆的那一问就是二次确认。
- **序号 `#n`**：右上三个列表每个对象前有淡色的 `#n`，是它在规范顺序里的位置（`port::order`）：会话是
  用户会话按建会话的时刻新的在前，流程按名字，作业按 ID（即创建顺序）。序号是临时的，列表变了就重排；
  过滤时不重编。工具参数写序号或 ID 都行。
- 三个标签用同一套状态符号与颜色：`●` 正在做（主色）、`◐` 等你（提醒色）、`✓` 完成（绿）、
  `✗` 失败（红）、`○` 空闲 / 没轮到（淡）、`⏸` 暂停 / 停用、`■` 已停止、`↺` 要重做；名字用正文色，
  次要信息用淡色。
- **右栏的键只管界面**：导航、展开收起、切对话区、看（`v`）、话头（`n` / `m`）。流程、作业标签不放
  操作的键——操作一多，键就记不住，而对话里说得清楚、留得下记录。会话标签照旧（§5.2）。站上只有人能做的决定
  用斜杠命令（§5.3）。
- **运行、触发里面的会话只在这里处理**：选中它切到对话区，插话、答提问、批权限。别的会话的工具
  动不了它们（architecture §8.5）。

### 5.2 会话标签

**上半**：人发起的会话（新建的、分叉的，分叉的末尾标 ⑂）。流程、作业开出来的会话不在这里，
从流程、作业标签进。第一行是 `＋ 新建会话`（选中它左边是草稿，Enter 进输入框；也可以在输入框里
`/new`），第一句话提交时才建出会话。
会话、流程、作业都是项目级的（需求 §1「项目级」），所以不再逐行写项目。

```
＋ 新建会话  Enter · 或在输入框里 /new
▾ #1 ◐ 重构认证模块            code  41.0k
     goal ● 迁到 OAuth，测试全绿 · 第 2/256 轮
     todo ▸ 2/7  ▶ 实现 provider  ☐ 迁移 session 存储 …
▸ #2 ○ 昨天的调研              code   8.0k ⑂
▸ 已关闭 (6)
```

关闭的会话不删：列表末尾是 `▸ 已关闭 (n)`，缺省收起，展开后按关闭的时刻新的在前。选中它左边是那个会话，**只读**
（输入框写着"已关闭 · o 重新打开"）；`o` 重新打开，回到上面的列表；`d` 删除（转录、附属数据连同子 Agent 的侧链一起删，
需二次确认，删了就没了）。批量清理在对话里说（`session_delete` 工具），程序不定保留策略。

| 选中的行 | 操作 |
|---|---|
| 会话 | Enter 打开 · `n` 回到草稿 · `r` 重命名 · `x` 关闭（需二次确认） |
| 已关闭的会话 | `o` 重新打开 · `d` 删除（需二次确认） |
| goal | Enter 修改 · `p` 暂停 / 恢复 · `x` 清除（需二次确认） |
| todo | → 展开全部条目（只读） |

选中会话 → 左边是它的主 Agent 会话；它的 goal 与 todo 在对话区顶部面板（§4.3）。

**下半**：选中主 Agent 的拆分树。子 Agent 与任务用图标区分：`◆` 子 Agent（主色），任务按种类
`$` shell、`◉` monitor、`λ` 程序、`⚙` MCP。选中哪个，左边就切到哪个：子 Agent 切到它的会话，
任务切到它的输出。

```
◐ 主 Agent                              等你   41.0k
├ ▾ ◐ ◆ 审查认证改动  reviewer     等你批准  12.0k  8m00s
│ ├ ● $ cargo test  shell            运行中         2m00s
├ ● ◉ tail -f app.log  monitor       运行中        15m00s
└ ▸ 已结束 (4)
```

| 选中的节点 | 操作 |
|---|---|
| 子 Agent | Enter 进入它的会话 · `m` 发消息 · `s` 停止（需二次确认） |
| Shell / 监视器 / 程序 | Enter 查看输出 · `s` 停止（需二次确认） |
| 已结束的 | 缺省收在 `▸ 已结束 (5)` 下面 |

### 5.3 流程标签

**上半**：这个项目能用的流程定义，展开是它**还没结束**的运行（在跑的、等人的、暂停的）。内置的与插件带来的
流程在名字前标 `◎`（只读，各项目都有），项目自己的不标；项目里存一份同名的就取代它。

列表末尾是 `▸ 已结束 (n)`：完成与取消的运行都在这里，缺省收起。展开后平铺、不按流程分组，结束时刻新的在前，
每行写主题、所属流程、站数、用时、token；`/` 过滤同样匹配流程名。只列最近 50 条，末尾一行 `… 更多`，
选中按 Enter 再取 50 条；取满过一页时标题写 `已结束 (50+)`。这样常用的流程展开后不会大半是历史，定义被删了、项目不再受信、改了名，它的运行也照样看得到。

```
▾ #1 ◎ 需求到上线    feature-to-ship  内置  2 个在跑
      ● 支付重试  运行中          站 3/7 实现   14m  88k
      ◐ 导出 CSV  等待：待确认评审汇总  站 6/7    1h  120k
▸ #2 ◎ 发布检查      release-check    插件 xforge
▸ #3   周报          weekly-report    项目
▾ 已结束 (12)
      ✓ 登录限流    需求到上线   7/7 站  42m  64k
      ✗ 商城风险    发布检查     2/5 站   3m  12k
      … 更多
```

| 选中的行 | 左边对话区 | 下半 | 键 |
|---|---|---|---|
| 流程定义 | **不动**（流程定义没有会话） | **流程设计**：分层节点图（并行用 ∥），再一站一行写执行方式、skill、出口，汇合的站右边写 `← 等 a、b`；选中一站按 Enter / `v` 用浮层看**这一站的配置**（执行、skill、出口、前一站 / 下一站、定义里它那段 YAML） | 选中即展开运行（← 收起后不再自动展开）· `v` 原始 YAML · `n` 新建 / `m` 说这个流程（改、删、启动一次运行）：回到用户会话放话头（§5） |
| 运行 | 这次运行的**主会话**，顶部面板是运行进度 | 这次运行的整棵树（下面） | `m` 说这次运行（暂停、恢复、取消、重跑） |
| 已结束的运行 | 同上；运行已结束，在主会话里说的话不影响运行，底栏提示一次 | 同上；框标题写归属：左 `登录限流 · 流程「需求到上线」`，右 `定义 3f2a91c`，定义与现在的不同加 `· 已改过`，定义没了加 `· 已删除`（右边的标题至多占一半宽，所以流程写在左边） | `m`（重跑、清理）；← 收起「已结束」 |
| `已结束 (n)` | 不动 | 空 | → / ← / Enter 展开收起 |
| `… 更多` | 不动 | 空 | Enter 再取 50 条 |

流程还有没结束的运行时，右下"流程设计"框的右边写 `🔒 2 个运行未结束，不能改`：这时在对话里改、删这个
流程，实例都会拒绝（architecture §8.5）。运行的主会话在对话框标题右边写 `流程「…」› <主题> › 主会话`。

**下半**：选中运行的整棵树——主 Agent、各站、站的任务，每个有会话的节点下面再挂它的子 Agent 与任务
（Shell、监视器、程序……），一层层往下。站**不缩进**，进展靠颜色读：做完的正常色、
正在做的主色、等人的提醒色、没轮到的淡色；汇合的站标 `← 等 a、b`。有子 Agent 的站缺省展开，→ / ← 收放。
有会话的节点在名字后面淡色写**模型**（不同的站、子 Agent 可以用不同的模型、不同的 provider；子 Agent 写它的
agent 类型再跟实际模型：`explore · claude-sonnet-5-5`）。
状态**不写字**（符号与颜色已经说了），右边紧凑右对齐地放用时与 token：`9m40s, 12.0k/4.5k`（输入 / 输出，缓存不单列；会话标签的拆分树同样）；
未达标的原因例外，用红字写出。

```
  ● 主 Agent  opus-4                  1h20m, 21.0k/7.8k
  ✓ 收集需求  session                 7m00s, 3.0k/900
  ✓ 设计  session  独立会话 · sonnet-4  15m00s, 6.0k/2.4k
▾ ● 实现  agent × 2                   9m40s, 12.0k/4.5k
    ├ ● ◆ 后端  deepseek-chat                9.0k/3.0k
    │   └ ● $ cargo test                        2m10s
    └ ✓ ◆ 前端  haiku-4                      5.0k/2.0k
  ○ 代码评审  agent
  ○ 文档评审  agent
  ○ 评审汇总  confirm  ← 等 代码评审、文档评审
```

选中主 Agent → 主会话；选中站 → 有独立会话的站切到它，其余的站在主会话里做、切到主会话；
选中站里的子 Agent → 它的会话（面包屑 `流程 › 运行主题 › 子 Agent`；流程、作业开出来的会话，面包屑从「流程」「作业」起）；
选中 Shell、监视器这类没有会话的任务 → 看它的输出（只读）。
站上只有 `m`：话头写明运行、站与它在等什么，返工到这一站、重试在对话里说。**确认、驳回、放行、强制放行只有人能做**
（design/flows.md §4），模型没有这几个工具，所以也不是"在对话里说"，而是人在输入框里打：`/confirm`、`/reject`（要理由）、
`/release`、`/force`（要理由），写法 `[运行] [站] [理由]`。运行不写是流程标签里选中的、或左边正对着的那次运行；站不写是这次
运行里唯一在等这件事的站，有几站在等就提示写哪一站。打出来的命令不进会话，直接发给实例，记成实例主人做的。
导出与导入流程包也在输入框里：`/flow:export <包> [文件]`、`/flow:import <文件> [--force]`（flows.md §7.12），导入的结果摆在浮层里。
打回也可以这样打：`/rework [运行] <站> [理由]`，站一定要写（打回的目标），理由给重做的站看；模型也能打回（`flow_rework`）。
流程包的运行还有一套按站名的地址（`/xforge:apply`、`/xforge:check <理由>`、`/flow:xforge <主题>`），见 §4.5 的「流程的地址」。

### 5.4 作业标签

**上半**：作业列表。

一行一个作业，不分类：

```
#1 ○ 每日巡检  0 9 * * *          下次 11-17 09:00  上次 ✓
#2 ● 周报流程  0 10 * * 1         正在跑 12m       上次 ✓
#3 ⏸ 月度归档  0 0 1 * *                          已停用
#4 ⏸ 依赖巡检  0 */6 * * *        自动停用：连续 3 次失败
```

今日额度用完时底栏提示一次（`unattended work used up today's budget …`），并作为待处理事项进通知与"离开期间"
（architecture §8.10）；之后到点的触发记 `– 已跳过：今日额度用完`。`sandbox.unattended_network` 是 `degraded` 时
由 `/doctor` 报出。

选中作业 → **左边不动**（作业没有会话）；新建、修改、删除回到用户会话里说（§5）。

**下半**：作业的定义、执行情况（次数、成功 / 失败 / 跳过、成功率、平均耗时与 token），下面是触发记录。

```
触发    0 9 * * *（下次 11-17 09:00）· 错过补跑：是
状态    启用
护栏    超时 30m · 单次 2.0M · 重叠时跳过 · 连续失败 3 次停用 · 今天 1.2M
提示词  检查昨天的错误日志并总结            ← 简单作业
skills  log-triage
场景    ops · 模型 缺省
流程    ▸ 需求到上线  Enter 跳到这个流程     ← 流程作业：跳到流程标签里它的位置
主题    每周发布
执行 3 次 · 成功 2 · 失败 1 · 跳过 0 · 成功率 66%
成功的平均耗时 1m32s · 平均 7.8k tokens · 合计 15.6k
触发记录 · Enter 打开那一次
11-17 09:00  ● 运行中 12m   1.1M  → 会话「日志巡检」
11-16 09:00  ✓ 完成  工具 12 次 · 改 3 个文件   1m38s  8.2k  → 会话「日志巡检」
11-15 09:00  ■ 已中止：超时 30m   30m  640k
11-14 21:00  – 已跳过：上一次还在跑
11-14 09:00  ✗ 失败：provider 返回 429
```

简单作业的每次触发记下它做了什么：调了哪些工具各几次、出错几次（无人值守的权限询问直接按拒绝，也在里面）、
改了哪些文件；行上写摘要，`v` 浮层与 `job_history` 写明细。
护栏里被全局上限压过的值标 `（全局上限）`。流程作业的护栏记在它起的运行上：超了**暂停**那次运行（不取消，
工作留着，进待处理），触发记录写 `■ 已暂停运行：超出 2.0M`。

选中一条触发记录 → 左边切到那一次的会话（流程作业是那次运行的主会话）。作业开出来的会话不在
会话标签里，这里是进去的地方，所以触发记录留在下半。简单作业的触发 → 展开是那个会话的子 Agent 与任务（带模型），
选中切过去；流程作业的触发 Enter 跳到流程标签里那次运行。

| 键 | 动作 |
|---|---|
| → / ← | 展开 / 收起一条触发记录的树 |
| `v` | 用浮层看全文：定义、执行情况、全部触发记录 |
| `n` / `m` | 回到用户会话，放进新建 / 说选中的作业或触发记录的话头（如 `作业 #1「每日巡检」：`、`作业 #1「每日巡检」11-14 09:00 那一次：`）；启停、立即运行、停下、删除在对话里说 |

### 5.5 离开期间

接入实例时，如果上一次脱离之后实例里攒下了"等人处理"的事（architecture §8.10），先弹一个浮层：

```
╭ 离开期间（3h20m）───────────────────────────────╮
│ › ◐ 运行「导出 CSV」等你确认：评审汇总            │
│   ◐ 运行「支付重试」搁置：上线                    │
│   ✗ 作业「依赖巡检」失败：provider 返回 429       │
│   ⏸ 作业「依赖巡检」连续 3 次失败，已自动停用     │
│   ⛔ 今日无人值守额度用了 80%                      │
│                         Enter 去处理 · Esc 关掉   │
╰─────────────────────────────────────────────────╯
```

Enter 跳到那一项（与 ^R 落点一样），Esc 关掉；之后照常用 ^R 走待处理。配了通知出口的照样有这个浮层——
通知只是把事送出去，回来时仍从这里接着处理。没有攒下的事就不弹。

## 7. 全局键位

Claude Code 也有的键，含义与它一致；Conix 独有的功能用 Claude Code 没占用的键。命令键只用 Ctrl+字母（§3），
写成 `^G` 这样；F1 留着，因为人人都知道它是帮助。

| 键 | 动作 | 替代 | 与 Claude Code |
|---|---|---|---|
| ^G | 切块：输入框 → 右上 → 右下 → 输入框（§3） | 点击 | Claude Code 用它开外部编辑器，Conix 没有这个功能 |
| ^N | 换到下一个标签（会话 → 流程 → 作业），焦点进右上 | 点标签头 | Conix 独有 |
| ^B | 宽屏时收起 / 展开右栏；单栏时切换显示哪一栏 | | Claude Code 用它把正在跑的 Bash / 子 Agent 放到后台；Agix 协议暂无对应能力，等有了再议 |
| ^X | 退出：弹出选择——后台运行（实例继续，之后 `conix attach` 接回）/ 直接退出（停止实例）/ 返回 | `/quit` | Conix 独有 |
| ^H / F1 | 帮助浮层（当前焦点的全部键位与鼠标操作）。输入框里有字时 ^H 是退格：有的终端退格键发的就是它 | `/help`、空输入框或右栏里按 `?` | 一致（`?`） |
| ^R | 跳到下一处待处理；提问框在等时进提问框 | 点角标 | Conix 独有（Claude Code 是搜历史，Conix 没有） |
| ^O | 看转录（详细）/ 回输入框（§4.2） | 点转录 | 一致（ctrl+o 看详细） |
| ^T | 收放顶部面板（goal / todo、运行进度），焦点回输入框 | 点面板标题线 | 键一致，todo 在面板里 |
| Shift+Tab | 轮换权限模式 | | 一致 |
| Esc | 运行中：中断；否则退一步（§3） | | 一致（中断） |
| ^C | 运行中：中断；空闲时第一次清空输入，第二次脱离 | | 一致（Claude Code 是退出） |
| ^D | 输入框为空：第一次提示、再按一次脱离；有字时删除光标后的字符 | `/quit` | 一致（Claude Code 是退出） |
| ^L | 重绘 | | 一致 |

只为兼容认、不列进帮助和底栏的键：Alt+Enter 换行，Alt+← →、Alt+B / Alt+F、Ctrl+← → 按词移动。它们是各家
终端按 Option+← 之类时自己发出来的编辑键（macOS 终端发的是 Esc b / Esc f），不是 Conix 的快捷键。

| 符号 | 含义 |

## 9. 加载、空状态与错误

| 情况 | 显示 |
|---|---|
| 列表正在加载 | 一行 `加载中 …`，不阻塞其他区域 |
| 列表为空 | 一行提示，并说明下一步可以做什么，例如 `还没有流程 · Enter 在对话里设计一个` |
| 命令失败 | 底栏显示错误，Esc 关掉；列表加载失败时显示 `✗ 加载失败 · r 重试` |
