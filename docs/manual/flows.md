# 流程

流程是按站推进的多步工作（流程库来自 Harnix）。**流程定义**有三层：内置的、全局的（`~/.conix/flows/`，
名字前标 `◎`）、项目自己的（`<项目>/.conix/flows/`，随项目提交，**项目受信才读、才写**，见 `/trust`）。

## 新建与修改

都在对话里说：每个会话都有流程工具（`flow_create`、`flow_update`、`flow_validate`、`flow_dry_run` ……）。
流程标签里 `n` `e` `d` `R` 把话头放进输入框（新建、修改、删除、启动一次运行）。还有没结束的运行时，
流程不许改、不许删——先取消或等它们跑完。

## 流程标签

上半是流程定义，展开是它**还没结束**的运行；末尾 `▸ 已结束 (n)` 是完成与取消的运行，不分流程、结束的新的
在前，一次取 50 条，`… 更多` 再取。

| 选中的行 | 左边 | 下半 | 键 |
|---|---|---|---|
| 流程定义 | 不动 | 流程设计：节点图，每站的执行方式、skill、出口 | `v` 原始 YAML · 下半选一站 `Enter` 看它的配置 |
| 运行 | 这次运行的主会话 | 主 Agent、各站、站里的子 Agent | `p` 暂停 / 恢复 · `x` 取消 |
| 已结束的运行 | 同上（在那里说话不影响运行） | 同上；标题写出它跑的定义，改过、删了会注明 | 无 |

站上的键：`c` 确认、`a` 放行（搁置的站）、`f` 强制放行、`r` 返工到这一站、`t` 重试。

## worktree

流程写 `workspace: worktree` 的运行不直接改项目，在仓库根的 `.wkts/<运行>/` 里干活（分支
`conix/flow/<运行>`），主仓库的 `git status` 看不到它。运行结束后合回、保留分支还是丢弃，在对话里说。
