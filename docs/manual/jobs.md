# 作业与护栏

作业是定时的无人值守工作：**简单作业**到点开一个会话、把提示词作为第一轮发出去；**流程作业**到点起一次
流程运行。cron 是 5 段（分 时 日 月 周），按本地时区。

## 新建与修改

在对话里说，每个会话都有作业工具：

| 工具 | 作用 |
|---|---|
| `job_validate` | 校验一份定义，不存：下 5 次触发时刻、护栏实际生效的值、存不进去的原因 |
| `job_save` | 新建或修改（`kind: simple` 写提示词，`kind: flow` 写流程、主题、输入） |
| `job_list` / `job_show` | 列出 / 看一个 |
| `job_history` | 触发历史，可翻页、按结局筛，每次写出它做了什么 |
| `job_run` | 立即跑一次（这一次可以换主题或补一句） |
| `job_stop` | 停下正在跑的那一次 |
| `job_enable` / `job_delete` | 启停 / 删除 |
| `work_list` / `work_show` | 所有作业的触发与流程运行一次查 / 一次触发的详情与它的运行时目录 |
| `work_cleanup` | 清掉早于某个时间的触发记录与运行时目录（先列出来，问过你再清） |

作业页的 `n` 放新建的话头、`m` 放选中的作业或触发记录的话头。启停、立即运行、停下、删除都在对话里说，
界面上不放这些键。作业触发出来的会话对作业只能看，不能改自己的作业。

**定义随项目提交**（`.conix/jobs.json`），团队共用；**启用与否只属于这台机器**：克隆下来的仓库带着作业，
在你的机器上缺省是停用的，看过再启用。项目受信才读、才写作业定义。

怎么说才好，帮助浮层（`Ctrl+H`）翻到「样例」页有几句例子，比如「每天 9 点检查昨天的错误日志，用三五行回报」。

## 流程包带来的作业

流程包可以在 `bundle.yaml` 里写几个**建议的作业**（`jobs:`，每条与 `jobs.json` 的一条同形）。`conix flow install <包>`
时列出来（ID、名字、cron、做什么），包装好后再问一句要不要加；`update` 只问新版新带来的。

- 加进来的写进项目的 `.conix/jobs.json`，在这台机器上是**停用的**：在作业标签里选中、`m` 在对话里说启用它才跑。
- 项目里已有同 ID 的作业不加也不改，计划里会标出来。
- `--jobs yes` 不问就加，`--jobs no` 不加；给了 `--yes` 而没写 `--jobs` 就不加（会说一声）；`--dry-run` 连作业一起列。
- 有实例在跑时它会重读作业，作业标签跟着变。
- `conix flow remove` 不删作业，只列出哪些作业起的是这个包的流程（它们之后会因为找不到流程而失败）。
- 流程作业只能起这个包自己的流程；cron 写错的包装不进来。

## 作业标签

| 键 | 作用 |
|---|---|
| `v` | 浮层看全文：定义、统计、全部触发记录与每次的明细 |
| 下半 → / ← | 展开 / 收起一次触发：简单作业是那个会话的子 Agent 与任务（带模型） |
| 下半 `Enter` | 打开那一次的会话或运行；流程作业的"流程"一行跳到流程标签 |
| `n` / `m` | 新建 / 说选中的这一项的话头 |

## 运行时目录

每次触发一个目录：`.conix/state/conix/job-runs/<作业>/<触发时刻>/report.json`，实例在起来时与结束时写：结局、
耗时、用量、做了什么（审计）、会话与模型、最后一轮回复的末尾。会话里 `work_show` 读它；流程运行的在
`.conix/state/conix/runs/<运行>/conix-report.json`。

## 护栏

无人值守的工作跑飞、挂住、叠起来时把它停下。三层上限，下层只能更紧：`conix.yaml` 的缺省与天花板
（见 [配置](config.md#jobs)），作业自己写的 `timeout` / `max_tokens` / `overlap` / `disable_after`
（取与天花板的较小值），以及实例级的每日额度与并发。

| 护栏 | 到了会怎样 |
|---|---|
| 超时 | 简单作业打断；流程作业**暂停**它起的运行（工作留着，进待处理） |
| 单次 token | 同上 |
| 重叠（到点时上一次还在跑） | `skip` 这一次跳过（缺省）、`queue` 排一个、`replace` 停下上一次 |
| 连续失败 | 在这台机器上自动停用（失败、超时、超额才算；人停的、额度用完、实例停了不算） |
| 每日额度 | 在跑的停下，当天剩下的触发都跳过 |
| 并发 | 满了就排队，排过一个周期还没轮到就跳过 |
| 网络 | 见下，不是"到了停下"，而是作业里命令能不能出网 |

人"立即运行"的不受重叠、并发、额度管；超时与单次上限照样管。

**单次 token 由引擎拦**：简单作业的 `max_tokens` 交给会话的预算，引擎在每次调用前按剩余判断，用完（含子 Agent）
就不再调用，那一次记成"被预算停下"；一次调用的输入就超过预算的，调用前就拦住。作业页与 `job_history` 里的 token 是
**计费口径**：未命中缓存的输入 + 缓存写入 + 输出，缓存命中不计，与 Agix 的预算、配额一致。会话页、流程页的 token 仍是全部。
旧记录按原来的口径（输入 + 输出）留着，没有改写，所以与新记录不能直接比。

**`CronCreate` 在作业会话里被拒**（流程作业起的运行也一样）：无人值守时让模型自己建定时任务，就绕出了作业与护栏之外。

## 网络

无人值守的会话里，没有 allow 规则的命令要沙箱兜得住、且网络受限才会执行（Agix 0.4 的
`sandbox.unattended_needs_network_policy`，缺省开）。所以作业有一项 `network`，写在 `conix.yaml` 的 `jobs.defaults` 或作业定义里：

| 值 | 含义 |
|---|---|
| `deny_all`（缺省） | 命令不能出网，本地命令照常跑 |
| `allowlist` | 只能到设置里 `web.allowed_domains` 列的域名 |
| `inherit` | 不管，照设置；网络不受限时，没有 allow 规则的命令会被拒 |

要在 `inherit` 下让某条命令跑，给它写 allow 规则，放项目设置 `.conix/settings.json` 的 `permissions.allow` 里，例如
`"Bash(git pull:*)"`。`job_validate` 对 `inherit` 会说明这一点，`/doctor` 的 `conix.jobs_network` 在缺省是 `inherit` 时报 degraded。
网络没有天花板：放开它是作业作者与这台机器的用户各自的决定。流程作业起的运行，每个站的会话都带同一个网络，
并按运行记一次（`state/conix/run-policies.json`），改了作业的护栏不影响已经在跑的运行。

## 审计摘要

简单作业的每次触发记下它做了什么：调了哪些工具各几次、出错几次（无人值守的权限询问直接按拒绝，也在里面）、
改了哪些文件。触发记录行写摘要，`v` 浮层与 `job_history` 写明细。
